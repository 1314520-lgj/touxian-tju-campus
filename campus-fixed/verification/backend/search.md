# 后端优化三：检索快照一致性和无命中短路

修改 search.py、zh_index.py：FTS 命中键与版本凭据在同一 SQLite 读快照内读取，避免旧命中集合配上新凭据造成漏结果。凭据与事项版本一致且无候选命中时，在加载快照映射和解析正文前跳过。索引缺失/过期、ASCII 子串、历史查询仍全量扫描；原有评分、顺序、同义词、原文切片、证据登记与最终公开版本检查不变。

新增 test_search_consistency.py，9 个实例：不加载无命中正文、只加载可能命中的事项、两个可确定复现的索引更新交错、5 类查询的完整结果/评分/顺序/证据与原扫描相等。修复前 4 failed / 5 passed，修复后与既有搜索测试合计 28 passed。完整回归 562 passed、8 skipped、0 failed、106 subtests passed，38.02 秒。

对随包历史数据库的临时副本实测（73 个公开事项，每组 7 次，预热后）：

| 查询 | 原耗时中位数 | 新耗时中位数 | SQL 语句数（含事务） | 加速 |
| --- | ---: | ---: | --- | ---: |
| 奖学金 | 162.952 ms | 45.582 ms | 608 → 55 | 3.57× |
| 国家奖学金申请材料 | 463.115 ms | 413.517 ms | 1516 → 1353 | 1.12× |
| 银河计数器（无命中） | 182.488 ms | 31.128 ms | 584 → 9 | 5.86× |
| GPA | 191.026 ms | 179.746 ms | 596 → 596 | 1.06× |
| 报名 | 370.553 ms | 331.309 ms | 1282 → 1027 | 1.12× |

五组响应完全相等，原样本数据库 SHA-256 未变。前后共用本轮 Store，单独比较搜索改动；基线方法直接从输入的前端交付 ZIP 提取。命令：python -m verification.backend.benchmark_search --baseline-zip <原1.9前端包>。

这些是本机后端函数测试，不是跨网络端到端或生产并发压测。高频词命中多数事项时节省较少，ASCII 为保留任意子串匹配语义仍走全扫，1.06× 属于计时波动，不能解释为算法提升。未验证真实 PostgreSQL、Meilisearch 和生产负载。
