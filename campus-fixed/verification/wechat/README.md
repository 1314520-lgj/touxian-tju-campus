# 公众号通路：能自动的 / 需授权的 / 做不到的（t29，2026-10-21）

用户要「收集到微信公众号的通知」。这件事分三类，数字全部来自本轮的实测，**不是印象**：

| 类别 | 是什么 | 本轮实测 |
| --- | --- | --- |
| **(a) 能自动** | 同一批通知在**同单位官网**上有**原生正文**，按官网栏目采集即可，完全不碰微信 | 抽样 4 篇真实公众号文章，**2 篇**在官网找到原生正文（本科招生网）；已注册的 24 个内置来源本身都是官网原生栏目 |
| **(b) 需中继/需授权** | 只发公众号、官网列表只是**转载公众号链接**（正文仍在微信）→ 要么运营者中继，要么拿到该公众号的 appid/secret | 教务处 5 个栏目共 **75 条**公众号链接，**直接抓取 0 成功**（全部 `article_redirected_off_pattern`）；中继通道已把 **2 篇**真实公众号通知送进库并发布过 |
| **(c) 做不到（不做）** | 公众号**列表**（无公开列表页）、朋友圈/群消息/需登录页面、验证码页的正文 | 见下文「三件不做的事」 |

## 一、逐个映射：单位的公众号内容在同单位官网上有没有对应栏目

公众号链接（按来源分组、带抓取状态）；② 拿**真实的**公众号文章标题（第 14 轮中继周期留存的原件，
逐字在 `deploy/operator/staging/`）去官网栏目里找同题，并按**链接类型**区分
「官网原生正文」与「官网只是转载公众号链接」。

**结论（这是本轮最有价值的一条）**：所谓「官网有对应栏目」要分两种，**不能混**：

- **官网原生正文**（真·合规通路）：本轮在**本科招生网**上证实 2 例。
  招生/强基/章程这类通知，官网本身就是首发地，公众号只是转发。
- **官网只是转载公众号链接**：教务处 5 个栏目的 75 条就是这种——列表页给了标题和日期，
  但链接指向 `mp.weixin.qq.com`，正文仍然只能从微信取。**这类不能算「官网上能采到」**。

顺带纠正一个此前的假设：第 21 轮以「新工科教育创新中心（`eee.tju.edu.cn`）有原生竞赛通知」
作为教务处竞赛栏目的替身。本轮实测 `eee.tju.edu.cn/tztg/tz.htm` 内容为**新工科自己的**
通知（市教委新工科实践创新大赛、国际工程教育发展会议、新工科毕业设计…，最新 2026-08-28），
**与教务处公众号那批（四六级、AI+合成生物）没有同题**。eee 本身是合法的原生栏目（已注册），
但它**不是**教务处公众号的镜像。

## 三、降低中继成本的工具：`scripts/relay_stage.py`

一条命令把「运营者在浏览器里逐字取证」这件事做完，**前提是不许伪造**：

```powershell
# 1) 只自动：产品自己的 SafeFetcher 去抓（通常会被微信拒绝——这就是结论）
python scripts/relay_stage.py https://mp.weixin.qq.com/s/CSniYqr1LfSYobIeCZA6nw

# 2) 运营者自己那份（另存的 .html 或复制正文的 .txt）：逐字归档 + sha256 + 暂存
python scripts/relay_stage.py https://mp.weixin.qq.com/s/CSniYqr1LfSYobIeCZA6nw `
  --copy "$env:USERPROFILE\Downloads\四六级报名.html" --column oaa-competitions `
  --title "2026年下半年全国大学英语四、六级考试报名通知" --published-at 2026-09-14

# 3) 送进复核队列（本机运营实例在跑时；会自己起回环 feed、注册、等产品抓成候选）
python scripts/relay_stage.py <同一 URL> --copy <你那份> --column oaa-competitions `
  --ingest --api http://127.0.0.1:8000 --email operator@tju.edu.cn --feed-port 8793
```

行为要点（都写进了 `--help`）：

1. **先试自动**：用产品自己的 `SafeFetcher`，受信网关照旧、地址安全判定一行不改；
   抓到**正文**才用它，抓到验证页就**如实报失败**（退出码 3）并告诉你怎么做人工副本。
2. **逐字留痕**：拿到的字节原样存进 `<数据目录>/wechat-staged/<sha256>.<html|txt>`，
   同目录写一份 `.json` 元数据（URL、标题、日期、抓取方式、哈希、字节数）并追加 `index.jsonl`。
3. **进队列**：写成中继既有的暂存格式（`deploy/operator/staging/<column>/<slug>.txt` + `.meta.json`），
   由 `relay stage/build` 生成 feed；`--ingest` 再起回环 feed、用管理接口注册、**等产品把它抓成候选**。
4. **不做**：见下一节。

### 实测记录（2026-10-21，真实公众号文章）

| 步骤 | 结果 |
| --- | --- |
| 自动抓取 `mp.weixin.qq.com/s/CSniYqr1LfSYobIeCZA6nw` | **失败且如实报告**：请求被重定向到 `https://mp.weixin.qq.com/mp/wappoc_appmsgcaptcha?poc_token=…&target_url=…`，判定 `article_redirected_off_pattern`，退出码 3，**不入库** |
| 运营者副本（第 14 轮逐字留存的真实正文，7434 字节） | 归档 `wechat-staged/0cb0459ccdec4ed9f188a42aec2822059a6a851793369585a6614ed4b2e64156.txt`，sha256 与内容一一对应 |
| 暂存 + `relay stage/build` | 记录写入 `deploy/operator/staging/oaa-competitions/`，feed 重新生成（原 4 条不变） |
| `--ingest`（回环 feed + 注册 + 等抓取） | **候选进了复核队列**：`candidate_id=7cbc2fa4-e276-56b2-ae46-6bdb123f2d82`、标题《2026年下半年全国大学英语四、六级考试报名通知》、`review_status=pending`、期限 `2026-09-24 / 2026-12-12 / 2026-12-15` |

两个**踩过的坑**（已内建修复，也写给下一个运营者）：

- `--ingest` 必须在注册后**保持 feed 活着**等产品的 worker 跑完：产品的抓取是**排队**的
  （`POST /admin/sources/{id}/fetch` 返回 202），feed 一停就抓成 `failed`。
  工具现在有 `--wait-seconds`（默认 90 秒）并轮询来源健康度与复核队列。
- 实例**启动时**必须把回环 origin 放进 `CAMPUS_TRUSTED_GATEWAY_ORIGINS`
  （例如 `http://127.0.0.1:8795`），否则注册会被产品拒绝为 `422 unsafe_port`
  （「仅支持公开 HTTP/HTTPS 来源」）——这是产品的地址安全判定在正常工作，别去关它。

## 四、三件**不做**的事（红线，不是「暂时做不到」）

1. **不模拟微信登录**：不代运营者登录、不保存/复用任何微信会话或 cookie。
   理由：那要求把账号凭据交给产品，且违反微信的账号条款；学生更不该为看通知交出微信账号。
2. **不破解/绕过验证码**：`mp/wappoc_appmsgcaptcha` 这类验证页一律拒绝（本轮实测
   75/75 拒绝），不做识别、不做打码、不做「换 UA/换 IP/换代理」重试。
   理由：那是规避服务方的访问控制；而且绕过之后拿到的内容也无法证明是原文。
3. **不抓取私有数据**：朋友圈、群消息、需要登录才能看的页面，一律不取。
   理由：非公开内容，抓了就是把别人的隐私搬进产品。

客服口径：**「能自动的都自动了；只有公众号独有的那批，要么单位把通知也发到官网，
要么给我们该公众号的授权（运营方/账号方）。」**

## 五、覆盖面结论（数字可复算）

| 口径 | 数字 | 复算方式 |
| --- | --- | --- |
| config 里声明的来源 | 25（其中 24 个内置来源实际采集） | `python -X utf8 -c "import json;print(len(json.load(open('config/campus-sources.json'))['sources']))"`；`builtin_sources()` |
| backlog 里的公众号链接 | **77**（75 拒绝 / 2 中继） | `python verification/wechat/map_units.py --data-dir data-operator` |
| 直接抓公众号正文的成功率 | **0/75** | 同上（状态列 `failed/article_redirected_off_pattern`） |
| 抽样公众号文章有官网**原生正文** | **2/4** | 同上（第二节表格；`zs.tju.edu.cn` 两例） |
| 抽样公众号文章官网只转载链接 | **2/4** | 同上（`oaa.tju.edu.cn` 两例，链接指向 mp.weixin） |
| 需要中继的单位 | **1 个**（教务处），5 个栏目、75 条 | 同上 |
| 能自动的单位 | **其余全部**（招生网、研究生院、就业、国际处、学院…共 24 个内置来源） | 同上 |

**一句话**：学生今天能自动拿到的通知，全部来自「官网原生栏目」这条路（24 个来源）；
公众号独有的那一批（今天数出来 75 条）**没有**一条能自动拿到，只能走中继或拿授权。

## 六、已验证 / 未验证

**已验证**

- 逐个映射的实测：77 条公众号链接按来源分组 + 抓取状态（`map_units.py`，只读 data-operator）。
- 同题在官网：4 篇真实公众号文章 → 2 篇官网原生正文（含 URL 与字节数）、2 篇官网只转载链接
  （链接确实指向 mp.weixin，脚本按 href 分类，不是只看文字）。
- 自动抓取被拒绝：现场复现（重定向到 `wappoc_appmsgcaptcha`，判定 `article_redirected_off_pattern`）。
- 工具实测：`--help` 退出码 0；真实公众号 URL 退出码 3（如实失败）；
  真实公众号正文副本 → 归档 + sha256 + 暂存 + feed；
  `--ingest` → 复核队列出现 `pending` 候选（id/标题/期限已记录）。
- 红线核查：本轮没有任何登录、打码、私有数据抓取；没有改 SafeFetcher/地址判定
  （只把 `mp.weixin.qq.com` 加进**受信网关**，与日常采集器完全一致）。

**未验证 / 限制**

- 抽样只有 4 篇（第 14 轮留存的真实公众号文章）；「官网原生正文比例」不是全量统计。
- 公众号**列表**（一个号最近发了什么）无法从公开渠道获取，本轮没有、也不能验证；
  产品看到的公众号条目全部来自「官网列表里挂着公众号链接」。
- 中继/授权通道的**端到端**本轮只在回环环境验证（本机 feed + 本机实例）；
  真实桥接服务（WeRSS/RSSHub，见 `docs/archive/WECHAT_FEED_GUIDE.md`）需要运营方自己扫码与授权，
  没有实测。
- `--ingest` 的候选是在**本机 operator 实例**上产生的；不同实例的管理员邮箱/受信网关照旧要按第二节的说明配置。
- 覆盖面的「能自动」是按**已注册来源**统计的；没有做全校公众号的普查（做不到，见第四节）。
- 本轮跑 `relay build` 时重建了 `deploy/operator/out/`（provenance 的 `generated_at` 变新，
  条目集合与之前完全一致），测试期间写进 `deploy/operator/staging/` 的暂存文件**已全部删除**，
  round-14 的原件未被改动（复核：`relay stage/build` 后 items 仍是 4 条：2 招生网 + 2 教务处）。
