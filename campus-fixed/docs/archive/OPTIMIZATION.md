# 1.0.1 整体检查与优化

本轮基于已交付的 1.0.0 运行版检查真实错误并修复，由事项/搜索、提醒/简报、页面三个代理分工处理，总集成负责异常输入、启动安全、交叉复核与独立打包。继续保持 51 项 API 和 domain-v1 DTO 结构。

## 学生能感受到的变化

| 问题 | 优化后的行为 |
|---|---|
| 截止提醒因排队、重试或免打扰而迟到 | 真正发送前再次核对当前版本和截止边界；超过期限的提醒取消。只有日期的期限，按上海时区保留整天，不编造官方截止时刻。 |
| 关键改期后又有普通标题更新，重要提醒丢失或重复 | 累计检查用户尚未确认的版本，依据最后一次关键变更去重；确认版本后取消排队的旧提醒。 |
| 停用、改时间、再启用简报后状态错误 | 排队任务执行前核对偏好；发送绑定当天简报，旧日重试不会发今天内容，已完成事项移出待处理列表。 |
| 旧审批或索引任务晚到，覆盖新数据 | 依据已批准版本和快照时间复核，索引收据只记录仍然有效的当前版本。 |
| 同名同日但面向不同学段、校区、年级的事项误合并 | 对照完整适用对象，保守归并；重要适用条件和必办状态变化也会提醒重新核对。 |
| 搜索同一通知挤满列表、混入旧转载日期 | 每事项版本折叠结果；当前字段证据与历史隔离，关键字段更新后旧转载只保留为历史。未抽取到结构化字段的正文仍可搜索。 |
| 标题出现“材料”便被列为材料清单 | 仅保留正文中有明确要求的原文连续片段，标题和宣传性提及不作为办理材料。 |
| 一次问期限和材料时只回答期限 | 分别整理问题涉及且有原文依据的字段，缺少依据时明确指出，保留期限冲突检查。 |
| 今天清单长期被过期和取消通知占据 | 当前行动与可展开的历史分开，日期不明确的事项继续显示待核对。 |
| 处理后面分页中的事项，列表折回前一百条 | 刷新保留已加载范围，并显示收藏、完成、删除的真实结果。 |
| 学院和提醒设置已保存，但切换页签又显示旧值 | 使用服务端保存结果更新设置缓存。 |
| 手机隐藏菜单或弹窗让键盘焦点跑到背景 | 隐藏导航不接收键盘焦点，弹窗可双向循环，Escape 关闭并归还焦点。 |
| 非法采集数据、JSON 或过大提交出现笼统服务器错误 | 返回符合契约的明确失败状态和请求编号；采集失败真实更新来源健康记录。 |
| 演示模式误继承生产数据库设置，首次启动无故要求 Node | 演示强制本地 SQLite，清除外部数据库/搜索配置并停用真实采集来源；包含预构建网页时只需安装 Python 依赖。 |

## 性能证据

测试中，同一事项 50 个匹配段落的证据写入从 50 次限制到最多 3 次，再按事项版本展示一条结果；不再用同一通知的多个段落占满搜索列表。信息流批量读取个人状态和来源目录；历史快照权限检查只遍历一次版本清单。这里没有宣称生产数据上的具体耗时提升，尚未进行真实负载压测。

## 验证

最终计数见 [ACCEPTANCE.md](ACCEPTANCE.md)。实际使用 SQLite 与 HTTP 验证 51 项成功响应；浏览器分别记录真实后端流程和明确使用模拟响应的专项界面测试。真实 Tesseract 中文 OCR 已运行，确认前没有上传原图或整段通知。

本轮新增回归覆盖上述错误；完整校园后端、前端单元、生产构建、独立目录启动和压缩包校验均需通过后才交付。真实校园采集、公众号授权、SMTP、PostgreSQL/Meilisearch、Docker 实机部署仍需在目标环境验证。

## 已有实例升级

先备份数据目录、环境配置及持久化密钥，再替换程序。公开 DTO 和 API 路径不变，不需要清空用户数据。

- 新增内部 `delivery_contexts` 仅保存简报 ID 和日期；旧版缺少日期绑定的待发简报会保守取消，避免发错天。
- 提醒计划新增内部语义和原始计划时刻字段；后台重规划时补齐。旧计划在不能确认截止依据时取消，而非迟到发送。
- 抽取规则版本升级后，只有显式重新抽取才重算旧快照；此前已审核候选重新进入人工核对，不自动批量改写公开事项。
- 旧证据和事件版本保留历史可读性；撤回事项继续阻断所有公开原文入口。
- 本轮未执行已有实例的数据迁移演练，也未证明生产邮件送达。模拟邮件只证明程序的状态和重试逻辑。

旧版交付包保留，新包单独提供清单、文件哈希和 ZIP SHA-256。
