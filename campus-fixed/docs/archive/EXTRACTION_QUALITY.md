# 提取规则 1.2：证据与验收

本轮改进针对会误导学生办理的具体问题：区间截止漏掉结束日期、活动日期混成报名截止、豁免一句话使正向材料全部消失，以及附件恢复后继续使用旧警告或旧附件证据。

## 已实现

- `报名时间：2026年10月10日至12日` 取明确区间结束日；跨年区间仅从明确连接的起点继承年份。孤立的月日跨年含糊时保留未知。
- 同一句内分别处理报名截止与活动时间，时钟不会从下一日期借入；活动/项目区间保留起止日期，统一标为发生时间。审核不能把发生时间改成申请截止。
- 括号内紧随完整日期的“周日”“星期五”作为日期标签，不再从发布日期额外推算一个日期。
- 支持原文年份中出现空格；证据仍保留原始连续文字，不改写成虚构原文。
- 材料否定按分句处理；明确填写的书名号申请表可列为材料，填写个人信息不会误列为材料。
- 排除的学生层次与持有的既往学历不作为正向适用人群；保留限制条件并要求复核。自愿办理不会自动变成所有学生的义务。
- 资格取消和“活动未取消”不作为活动取消；更正、延期、附件依赖缺失进入复核。
- `.doc`/`.xls` 的 OLE 二进制明确解析失败，提示需人工处理，避免把乱码当正文。
- 同一快照的抓取警告变化会使解析和候选缓存失效。成功恢复后旧抓取错误移除，新的候选仍要求核对；历史已接受版本保持可读。
- 原文经历 A→B→A 回退时，重新观察到 A 的计数进入候选缓存输入，产生待审核的新版本，避免直接返回旧已发布候选并跳过处理。
- 每个候选版本冻结当时的观察时间和计数；人工审核新版本复制同一输入，供事项层判断先后，防止迟到的旧候选借用当前观察时间覆盖新状态。
- 已记录 `snapshot_attachments` 时只使用当前成功附件；空数组代表没有活动附件，旧附件不会继续影响当前材料、日期及证据。旧数据未记录该字段时兼容既有附件选择逻辑。

解析版本为 `campus-body-1.1`，规则版本为 `campus-rules-1.2`。已有候选重新提取时升级版本并进入复核，保留历史候选，避免规则升级悄悄重写学生已看到的事项。

## 短官方语料核对

语料来自目录提交 `88e2588` 的 `fixtures/notice-corpus/official-notices.json`，核实日期为 2026-10-08：20 个官方页面的短摘录，每页不超过 25 字符；有 11 个可确定绝对日期字段、1 个年份未知的月日、4 个材料条目。每个样本保留原页面地址。

| 核对项 | 规则 1.1（8060b97） | 规则 1.2 |
| --- | ---: | ---: |
| 绝对日期及用途正确 | 7 / 11 | 11 / 11 |
| 额外或用途错误的绝对日期 | 5 | 0 |
| 漏提绝对日期及用途 | 4 | 0 |
| 材料正确 | 0 / 4 | 4 / 4 |
| 材料误提 / 漏提 | 0 / 4 | 0 / 0 |
| 字段集合完全匹配的摘录 | 12 / 20 | 20 / 20 |
| 未知年份保持未知 | 1 / 1 | 1 / 1 |

逐项结果保存在 `validation/extraction/evaluation-rules-1.1.json` 与 `evaluation-rules-1.2.json`，含语料指纹。可运行：

```powershell
python scripts/evaluate_notice_corpus.py --output validation/extraction/evaluation-rules-1.2.json
```

**这些数值不能称为完整公告准确率。** 语料为人工选择的短摘录，已经用于发现和修复规则，属于开发集，没有随机抽样或独立留出评估。这里比较绝对日期、日期用途和连续材料片段；没有给时刻、全篇适用人群、自动审核状态或生产采集成功率打分。全部摘录的 `requires_review=true` 表示上下文不足，并非提取器自动状态的评分标签。

原文“晚24时”只保留日期，不擅自变成翌日零点；工作日、满额截止、学院报送与学生截止等仍须结合完整原文核对。网页标题中的“2026届”也不能替代未核实的发布日期来推断年份。

## 回归验证

本轮最终相关检查为 **85 项通过**：新提取反例、既有提取审计、数据正确性审计及管线测试。新测试覆盖缓存警告加入/恢复、原文重新激活、空活动附件集、OLE 旧附件、历史候选保留、区间与多日期角色、括号星期、表单材料和审核用途约束。

既有人工更正测试改为明确构造规则 1.1 已接受历史记录，继续断言更正后的重要字段变化和收藏事项需关注状态；不再要求当前规则重复旧误判。测试使用真实 SQLite 和不可变快照，网络输入为明确标识的本地合成样本。

尚未完成学生真实使用试点、随机完整公告标注集、真实微信公众号授权采集或 Google Cloud 上线验证。本轮结果证明这些具体机制和回归成立，不能代替上述验收。
