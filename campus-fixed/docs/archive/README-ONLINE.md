## 启动

Python 3.12+，在应用根目录安装锁定依赖：

```sh
python -m pip install -r requirements.txt
python app.py
```

`requirements.txt` 引用 `requirements-campus.lock.txt`，不再使用另一套删减依赖。当前发行包不承诺提供 `wheelhouse/`；首次安装是否可离线，取决于部署方自己的包缓存。仅重建网页时需要项目规定的 Node.js 环境和锁文件。

`app.py` 默认读取根目录 `data/`，可用 `CAMPUS_DATA_DIR` 指向运营持久化目录；监听端口由 `PORT` 指定，默认 3000。该入口关闭开发验证码与公开 API 文档的默认暴露。环境文件示例只是配置参考，应用不会自动加载任意 `.env`；请通过启动环境、容器 `env_file` 或部署平台安全注入变量。

启动会检查数据目录可写性、SQLite 完整性和前端文件。目录只读、数据库损坏或缺少完整前端时明确失败。SQLite 自己恢复已提交的 WAL；入口不会删除 `-wal`/`-shm`，也不会自动把运营数据库复制到临时目录继续服务。运行数据与 `.server-secret` 须放在受控持久目录，重启保留密钥；生产使用显式 `CAMPUS_SECRET`。

完整 `dist/` 可直接读取；缺少完整 `dist/` 时，才会从完整 `web/` 原子复制前端。部署方应事先验证构建产物和目录权限，不假定所有托管平台都保留或剔除相同目录。启动入口的文件名约定属于部署配置，本版不承诺某个托管平台的自动探测行为。

### 单端口托管实例：`python serve_cloud.py`

托管沙盒（单公共端口、平台反向代理、无外部数据库）用同一个根目录的 `serve_cloud.py` 启动，读取平台注入的 `PORT` 并绑定 `0.0.0.0`。启动前与 `app.py` 一样校验数据目录可写性、SQLite 完整性与前端构建，关闭公开 API 文档。两种模式只差启动期环境默认值，不改变产品行为：

- `CAMPUS_CLOUD_MODE=demo`（默认）：库为空时一次性写入明确标记的合成演示事项（**【演示】**前缀，不可用于真实办理），打开开发验证码使无 SMTP 的实例可登录（验证码在登录界面直接显示），`CAMPUS_ADMIN_EMAILS` 首地址为实例管理员（默认 `demo-admin@touxian.local`），内嵌 worker 保持关闭。
- `CAMPUS_CLOUD_MODE=live`：与 `app.py` 相同的公开守卫（即使环境里继承了开发验证码变量也强制关闭），一次性注册 `config/campus-sources.json` 的官方来源，内嵌 worker 随之定时采集。

宿主域名在启动时未知，`CAMPUS_ALLOWED_ORIGINS` 写不到 ephemeral 域名；启动器因此放行"来源就是当前宿主"的写请求（与 `app.py` 本地开发等价的同源语义），跨站伪造请求仍被原守卫拒绝。`CAMPUS_PUBLIC_ORIGIN` 可显式补充白名单。生产真上线仍走 [生产配置示例](deploy/campus/.env.example)：`CAMPUS_ENV=production`、PostgreSQL、显式 HTTPS origin、持久 `CAMPUS_SECRET` 与真实 SMTP 收信验收。

## 数据更新与部署边界

发行样本中的 15 个来源默认停用，避免打开历史样本时意外启动外部采集。管理员须逐个核验并启用后再采集。页面会显示历史样本提示；确认已替换成正式运行数据后，维护者可移走 `PUBLIC_SAMPLE.json` 标记。公开通知可能引用校园网内部办理入口，保留这类学生浏览器链接并不允许服务器抓取私网来源。

2026-10-13 第 9 轮在**本机 operator 模式实例**跑通首个真实运营周期（非公网实例）：运营方从两个官网栏目逐篇取证，经 `deploy/operator/` 中继以授权 feed 送入产品，4 篇真实原文完成采集→抽取→人工审核（3 采纳 1 拒绝）→3 条事件发布，检索可召回，事件证据链接均为真实官网地址。该实例数据目录 `data-operator/` 与 `deploy/operator/out/`、`session.json` 均不进发行包（清单构建器拒绝后者）。周期证据 `verification/operator-cycle-1-2026-10-13.json`，规程 `deploy/operator/OPERATIONS.md`；暴露的日程日期抽取缺口立为任务 T19，强基计划通知待修复后随下一周期重发。

运行 worker 会推进持久化队列、提醒和启用来源的定时采集；是否成功须查看任务、来源健康和候选审核状态。为了只检查历史样本，可以设置 `CAMPUS_EMBEDDED_WORKER=false`，并且不启动独立 worker。不要把服务成功监听或健康接口成功视作来源、附件、SMTP或个人网关均已验收。

公众号正文可能需要平台验证或外部授权。获授权的 RSSHub / WeRSS feed 可按 [ADAPTERS](deploy/campus/ADAPTERS.md) 接入；本轮没有取得新公众号授权或绕过访问限制。维护者补充正文或附件时须保存授权依据和补充来源，新增证据重新进入审核，不直接自动发布。

Google Cloud 的 [部署材料](deploy/cloudrun/DEPLOY.md) 可作为待部署方案；本轮未创建 Google Cloud 项目、未部署 Cloud Run，也未核验真实校园出口、生产 SMTP、个人网关或真实学生试用结果。

## 升级、备份与发行

运营升级前保存数据库、原文快照、配置和应用密钥的一致性备份。运行中的 SQLite 不可只复制主文件后丢弃 WAL；应使用 SQLite 备份机制，或停止写入后取得一致性快照。恢复先在隔离实例核对数据与权限。

发行包从隔离副本生成，公开样本与合成演示分别标记，排除会话、验证码挑战、日历令牌、个人事项及偏好、真实凭据和私密快照；不得在原运营目录清理这些数据。实际打包、清理、哈希和验收证据以最终验收报告为准。
