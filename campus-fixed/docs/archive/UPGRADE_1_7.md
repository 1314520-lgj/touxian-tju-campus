# 偷闲·天大版 1.7.0 升级说明

产品版本 **1.7.0**，公共契约 **1.5.0**。本版针对用户源码中的个人推送隔离、公开变化历史、附件证据完整性和公开入口启动行为进行修复。历史样本与线上状态分开说明；本轮没有部署历史链接、创建 Google Cloud 项目、重新采集校园网站或真实外发提醒。

## 个人推送隔离

原全局 `CAMPUS_PUSH_ENDPOINTS` 广播方案已被替代，应用忽略该变量，不再使用默认 urllib 或 Apprise 外发个人事项。现在由维护者通过服务器 `CAMPUS_PUSH_USER_ENDPOINTS` 配置 JSON：

```json
{"11111111-1111-4111-8111-111111111111":["https://push.example.invalid/users/student-a"]}
```

示例中的用户 UUID 与地址是占位符。实际 UUID 来自登录后 `GET /api/v1/me` 的 `user.id`；目标须经用户确认实际收件人仅为本人。API 和 worker 使用同一映射，配置改变后重启相关实例。每人最多 4 个公网 HTTPS 443 目标，等价重复地址在本人列表内去重，跨用户共享规范化地址则双方拒绝。

网关须接受 JSON `title`/`body` 与 `Idempotency-Key`；此版本不承诺任意聊天平台 webhook 直连兼容。无需额外推送依赖，`requirements-push.txt` 保留为空的兼容入口；运行依赖统一通过 `requirements.txt` 引用校园锁文件。

`GET /api/v1/me/push-status` 需要登录，只返回本人 `available` 与 `reason`：`ready`、`unconfigured`、`invalid_configuration` 或 `shared_destination`，不返回目标、密钥或他人信息。未安全绑定时界面提示不可用，`PUT /api/v1/me/preferences` 选择 push 返回 **409 `PUSH_NOT_READY`**。旧排队任务丢失本人绑定后明确失败，不会落回广播。

发送前校验所有 DNS 地址，固定到核验的公网 IP，保留 TLS 主机名校验，拒绝私网、云元数据、混合 DNS 和重定向；载荷上限 16 KiB，传输有超时限制。系统 DNS 解析耗时仍由操作系统管理。发送前确定未外发的错误记为 failed；发送后结果不明或仅部分目标接受记为 unknown，保留既有发送认领与避免重复投递行为。

`ready` 仅表示服务器绑定配置可用。本轮通过模拟连接验证隔离和结果判定，没有真实个人网关或邮件外发，不能将通过模拟测试写成学生已经收到提醒。

## 完整的公开采纳变化历史

变化接口汇总历次已公开版本采纳的公开快照，按观测顺序列出同一文档的增删改写摘要，保留历史上已经公开的修改。首次采集没有比较对象，不显示为空修改。

未被公开版本采纳的中间稿不进入公共历史。若解析时缓存摘要曾比较未公开中间稿，公共接口改为对比前后已采纳原文，避免把未公开文本放进摘要。事项撤回后，详情、变化历史、搜索、证据和原文件入口一并阻断。

## 附件缺口与授权补充

用户提供的公开样本是截至 **2026-10-09** 的历史公开通知，旧包记录有 **161 个附件失败**。验证码页、登录/验证 HTML 和下载失败不能当作已解析文件；正文可读也不能证明附件或材料要求完整。

事项详情展示当前公开版本采纳证据中的附件访问受限、待解析或解析不完整提醒，学生可回原网页人工核对。程序不绕过验证码，不把失败附件静默宣称为完整资料。

维护者只能在取得授权后补充原文或附件，留存补充方式与来源，并把新增证据重新送入审核。补充内容不直接自动公开，也不把人工上传伪装成程序从学校原站核验成功。

## 持久存储、WAL 与启动

公开入口在应用启动时验证持久化目录、数据库及完整前端；导入入口模块不立即打开数据库或启动采集线程。外部环境配置继续适用生产保护，公开入口不提供开发验证码。

SQLite 的 WAL/SHM 交由 SQLite 恢复，入口不手动删除。持久开发密钥与运行数据配套保留，生产使用显式 `CAMPUS_SECRET`；重启不任意轮换密钥。数据目录只读、数据库损坏或前端不完整时明确失败，不自动复制运营数据库到临时目录继续提供陈旧内容。

完整 `dist/` 可直接读取，不要求启动时重写；需要回退到 `web/` 时先验证完整性，再原子复制前端。生产部署仍需 PostgreSQL、精确 HTTPS origin、持久密钥、真实 SMTP 和独立 worker，示例见 [deploy/campus/.env.example](deploy/campus/.env.example)。

备份运行中 SQLite 应使用备份机制或停止写入取得一致性快照，不得只复制主数据库并丢弃 WAL。运营升级和恢复都须保留数据库、原文、配置、密钥之间的配套关系。

## 检索与文档口径

本地 FTS5 以一元/二元切分缩小待扫描候选，近义词表在字面匹配不足时补充检索。最终命中沿用既有匹配、打分与排序，当前没有以 BM25 分数决定搜索排名。索引缺失、凭据过期或不适用时回退全量扫描，历史查询仍按原逻辑处理。

[README-ONLINE.md](README-ONLINE.md) 保留用户提供的历史链接用于追溯，本轮未证明它仍在线、展示固定数量通知或完成真实人工逐条审核。当前文档不再声称提供不存在的 wheelhouse、自动临时数据库回退或每次启动重生成密钥。

## 隔离发行与验收边界

发行包从隔离副本生成，明确区分历史公开样本和合成演示。清理会话、验证码挑战、日历令牌、个人事项及偏好等私密运行记录，并排除真实密钥、环境凭据和私密快照；不在用户原包或运营实例里执行清理。公开历史、原文证据和失败状态按可核验范围保留。

数据库一致性、清理范围、发行文件清单、包哈希、测试结果和跳过项 **以最终验收报告为准**，见 [ACCEPTANCE](ACCEPTANCE.md)。本文件不把历史报告的通过数量或跳过结果算成本轮验收。

本地验证覆盖隔离投递、共享目标、DNS/TLS/重定向、发送认领、公开历史、附件质量提示、启动持久性与相关界面行为。真实校园网络、公众号授权、生产 SMTP、个人网关实际送达、Google Cloud 部署和真实学生试用仍需目标环境验收；[Cloud Run 指南](deploy/cloudrun/DEPLOY.md) 为待部署材料。
