# 1.6 能力记录：变化可见性、中文检索索引与无障碍自动化

当前产品为 **1.7.0**、公共契约为 **1.5.0**。本文件保留 1.6 的实现背景，并修正检索排序与公开历史的说明；现行升级行为见 [UPGRADE_1_7.md](UPGRADE_1_7.md)，本轮测试结果 **以最终验收报告为准**。

1.6 当时处理 1.5 留下的三处缺口：

1. **变化摘要已落库但不可见** —— 1.5 已经在 `documents.change_summaries` 里写入每次采集相对上次的差异，但只有程序能读到。
2. **中文全文检索需要缩小扫描范围** —— 未配置 Meilisearch 时，检索遍历事项段落做子串匹配，已有打分与排序，但每次扫描工作量随正文总量增长。
3. **无障碍只有人工检查** —— `ui-polish.e2e.mjs` 覆盖了对比度、键盘焦点和动效偏好，但没有可重复执行的标准规则扫描。

## 一、变化摘要接入 API 与界面

### 新增接口

`GET /api/v1/events/{event_id}/changes`（公开，无需登录）

```json
{
  "event_id": "…",
  "version": 2,
  "changes": [
    {
      "snapshot_id": "…",
      "observed_at": "2026-10-08T12:00:00+08:00",
      "change": {
        "previous_snapshot_id": "…",
        "summary": "时间或期限可能有变化：改写 1 段。新增内容：请于2030年1月9日前提交确认表。",
        "counts": { "added": 0, "removed": 0, "rewritten": 1, "unchanged": 3 },
        "kinds": ["deadline_or_date_touched", "wording_revised"],
        "truncated": false
      }
    }
  ]
}
```

1.6 在契约侧加入 `ChangeSummary` / `EventChangeItem` / `EventChangeSummary`，并把 `ChangeSummary` 复用为可选的 `ParsedDocument.change`。当时契约为 v1.4；当前契约已是 **v1.5.0**，以 [openapi.v1.json](campus-contracts/openapi.v1.json) 为准。上面的 JSON 仅为合成结构示例，不是本轮真实通知。

### 三处必须保持的语义

- **首次采集不报变化。** 没有可比对的上一份原文时，`changes` 为空数组，而不是渲染成"有改动"。
- **只有被公开版本采纳的公开快照才会出现。** 1.6 只从当前版本映射取最近摘要，无法完整回看历史；1.7 汇总历次已公开版本的 `event_snapshot_versions`。未公开或未采纳的中间稿不进入公共历史，必要时只比较前后已采纳原文，避免摘要引用中间稿。
- **撤回即消失。** 事项撤回后该接口返回 404，与详情、检索一致。

### 界面

| 位置 | 呈现 |
| --- | --- |
| 事项详情 · 顶部横幅 | 有变化时提示"内容有更新"+ 最近一次摘要，一键跳到变化记录 |
| 事项详情 · 变化记录页签 | 1.7 逐条列出历次公开采纳原文的摘要、时间、增删改写段数与类型；涉及时间/期限时提醒重新核对 |
| 管理台 · 候选审核 · 查看解析全文 | 展示"相比上次采集"的摘要与段数统计 |

`parse_document` 保留相邻已解析采集之间的差异，供运营核对。公开历史则只使用已公开版本采纳的原文；若缓存摘要曾与未公开中间稿比较，1.7 会重新比较前后已采纳快照。两处范围不同，摘要可以不同，公共接口不能暴露未公开稿件。

## 二、中文检索：本地 FTS5 候选索引

当前实现通过 FTS5 缩小候选集合，再沿用既有子串匹配、打分与排序。虽然 FTS5 提供 BM25 函数，本项目没有以 BM25 分数决定当前搜索排名；旧版把这一能力写成“BM25 排名”不准确。

### 为什么用 FTS5 而不是分词库

中文没有词边界。SQLite FTS5 自带的分词器会把一整段汉字当成一个 token，因此索引前需要自行切分。本版采用**一元 + 二元切分**（`server/campus/zh_index.py`）：

> 任意长度 ≥ 2 的子串，都包含它自己的全部二元组。

因此"对一个词的 token 取 AND"永远不会漏掉一次子串命中。这条性质让索引**只能缩小工作量，不能改变结果**——也正因如此，它可以安全地放在既有打分器下面，而不必重写检索语义。

**没有引入 jieba 等分词库**，原因是分词会移动 token 边界，破坏上述超集性质；一个会悄悄漏结果的索引，比线性扫描更糟。

### 三条约束

- **纯汉字查询才走索引。** ASCII 词在既有扫描里按子串匹配（`gpa` 能命中 `gpa3.5`），token 索引做不到这一点。与其给出一个静默更小的结果集，不如整条查询回退到全量扫描（`zh_index.narrowable`）。
- **凭据过期就全量扫描。** 索引写入后同时写入 `local_index_receipts`（事项 ID → 版本号）。只有凭据版本与当前服务版本一致时才用索引缩小范围，否则该事项完整扫描。部分构建、索引失败、撤回都因此自动退化，不会产生漏检。
- **不截断结果。** 查询不加 `LIMIT`：限制条数会丢掉全量扫描本会保留的弱匹配。

### 近义词

`search.py` 内维护一份保守的校园近义词表（截止/截至、报名/申请/申报、材料/资料、成绩/分数/绩点等）。仅在**字面匹配不足 2 个事项**时启用扩展，扩展扫描打分扣减 1，并保留原有字面匹配候选。最终顺序仍按既有分数、历史标记和标题排序，不另作 BM25 排名承诺。

### 索引位置与降级

索引表 `campus_segment_fts` 与记录同库（SQLite）。`index_event` 任务在更新 Meilisearch 的同时刷新本地索引；未配置 Meilisearch 时它是唯一索引。数据库不是 SQLite（例如云端 PostgreSQL）或构建不含 FTS5 时，`LocalTextIndex.supported` 为 `False`，检索自动回到原有全量扫描，功能不受影响。

## 三、无障碍自动化

新增 `src/campus/tests/a11y.e2e.mjs`，用**真实 axe-core 4.10.2**（`src/campus/tests/vendor/`，MPL-2.0）在真实浏览器中扫描显式合成演示服务，不做任何路由拦截。

### 判定策略

- `serious` / `critical` 违规 → 失败。
- `moderate` / `minor` 违规 → 记录并打印，不阻塞。
- **ARIA 规则不允许"无法判定"**：axe 对 ARIA 规则总能给出结论，出现 `incomplete` 即视为标记含糊，按失败处理。
- `color-contrast` 的 `incomplete` 例外：渐变背景无法从计算样式推导，已明确交由 `ui-polish.e2e.mjs` 的像素级对比度检查覆盖，报告中标注为 deferred。
- **引擎缺失即中止**：找不到 vendored 的 axe 文件会直接报错，绝不退化成"零违规 = 零检查"。

### 覆盖范围

历史扫描目标包括未登录首页、登录对话框、主页面、事项详情与变化记录、移动端首页和导航抽屉，以及管理台页签。本轮实际覆盖场景与结果以最终验收报告为准。

### 本版修复

| 问题 | 修复 |
| --- | --- |
| 弹窗标题用 `<header>`，与顶栏构成两个 banner 地标 | 弹窗标题改为 `<div class="modal-head">` |
| 侧边栏用 `<aside role="dialog">`，`aside` 不允许该角色 | 改为 `<div>`，桌面端 `role="complementary"`、移动端 `role="dialog"` |
| 空状态、来源列表、个人事项、管理台多处 `h1 → h3` 跳级 | 补齐 `h2` 层级；空状态标题升为 `h2` 并保持 17px 视觉尺寸 |
| `.welcome-graphic` / `.filter-row` 在 `generic` 角色上挂 `aria-label` | 补 `role="group"` |

## 五、边界与已知限制

- 变化摘要来自**留存原文的逐段比对**，能指出内容增删改写；1.7 公共历史仅比较已公开版本采纳的原文，不替学生判断新的办理义务或具体截止时刻。
- 本地索引只服务**当前版本**的检索；勾选"包含历史版本"时仍走全量扫描，历史检索未加速。
- 近义词表是人工维护的小表，只覆盖校园场景中同义的措辞，不做主题联想。
- 无障碍扫描针对显式合成演示数据。真实接入来源后的内容形态不同（更长正文、附件），需要时应对真实数据再跑一次。
- axe 覆盖的是可自动判定的规则；键盘顺序、读屏语义、文案清晰度仍需人工复核。
